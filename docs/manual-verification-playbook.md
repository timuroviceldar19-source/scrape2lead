# Manual Verification Playbook: AutoService Radar KZ

## Цель
Добрать вручную 40 компаний для формирования sales-ready sample (итого 50 строк: 10 реальных + 40 ручных) в файле `exports/autoservice-radar-astana-real-sample-50.xlsx`.

## Распределение по категориям
Необходимо собрать данные равномерно по 4 категориям (по 10 компаний на каждую):
1. Автосервисы (СТО, ремонт двигателей, кузовной ремонт)
2. Шиномонтажи
3. Автомойки
4. Магазины автозапчастей

## Структура данных

### Обязательные поля
- **Компания**: Официальное название или бренд.
- **Категория**: Одна из 4 целевых категорий.
- **Город**: Астана.
- **Адрес**: Физический адрес с указанием района.
- **Телефон**: Основной контактный номер организации.
- **WhatsApp или другой канал**: Наличие рабочего мессенджера.
- **Источник**: Прямая ссылка на публичный источник данных (source_url).
- **Дата проверки**: Текущая дата в формате YYYY-MM-DD (checked_at).
- **Статус проверки**: `Проверено`, `Нужно проверить`, `Не дозвонились`, `Удалить`.

### Желательные поля
- **Сайт**: Официальный сайт компании.
- **Email**: Корпоративный email (info, sales и т.д.).
- **Telegram**: Наличие рабочего аккаунта.
- **Заметки**: Дополнительная информация (например, "только оптом", "ЛПР: Иван", "нет точного адреса").

## Правила качества (Quality Gates)
1. **Нет телефона = нет записи**. Не добавлять компанию без контактного телефона.
2. **Запрет дублей**. Не добавлять дубликаты по комбинации `Название + Телефон`.
3. **Только авто-бизнес**. Не добавлять компании, не относящиеся к 4 целевым категориям.
4. **Адрес критичен**. Если точного адреса нет, обязательно сделать пометку в поле `Заметки` и не считать строку полностью готовой.
5. **Source URL обязателен**. Каждая запись должна иметь ссылку на источник для прозрачности и аудита.
6. **Актуальность**. Поле `Дата проверки` (checked_at) всегда должно содержать текущую дату сбора данных.
7. **Конфиденциальность**. Собирать только B2B-данные. Личные данные сотрудников (мобильные номера менеджеров, если это не общий рабочий номер) не собирать.
8. **Право на удаление**. Если компания прямо просит удалить данные из базы, пометить статус как `Удалить` и не использовать в sample.

## Шкала "Полнота данных" (Completeness Score)
Оценивается от 0 до 100 на основе наличия ключевых полей:
- **100**: Телефон + WhatsApp + Адрес + Источник + Сайт/Email
- **80**: Телефон + WhatsApp + Адрес + Источник
- **60**: Телефон + Адрес + Источник (но нет WhatsApp)
- **40**: Телефон + Источник (но нет Адреса)
- **< 40**: Не использовать в sales sample (брак)

## Критерии "Готов к рассылке"
- **Да**: Полнота данных >= 80 И Статус проверки = `Проверено`.
- **Нет**: Полнота данных < 80 ИЛИ Статус проверки не равен `Проверено`.

## Порядок ручной проверки (Step-by-Step)
1. Найти компанию в публичном источнике (2GIS, Яндекс.Карты, Instagram, сайт).
2. Сверить категорию бизнеса с целевым списком.
3. Записать основной телефон.
4. Проверить наличие WhatsApp по этому номеру (через сохранение в контакты или web-версию).
 a. Если есть WhatsApp — записать в поле WhatsApp.
5. Записать точный адрес.
6. Добавить прямую ссылку на источник (source_url) в поле Источник.
7. Поставить текущую дату в поле Дата проверки.
8. **Проверить на дубли** в текущем XLSX-файле по названию и телефону.
9. Рассчитать и выставить оценку в поле `Полнота данных`.
10. Выставить `Статус проверки` = `Проверено` (если все шаги пройдены успешно).

## Daily Target и контроль качества
- **Скорость**: 40 строк за 2–3 часа (примерно 3–4 минуты на компанию).
- **Промежуточный контроль**: Каждые 10 строк делать быстрый duplicate check по всему файлу.
- **Финальная цель**: Минимум 45 из 50 строк (включая 10 изначальных) должны иметь полноту данных >= 80 и статус `Проверено` для отправки клиенту.
