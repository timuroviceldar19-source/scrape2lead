# Кейс: навели порядок в Bitrix24 с 4075 сделками за один день

> Все цифры — из логов реального проекта (июль 2026). Портал клиента — дистрибуция
> интерактивного оборудования, лиды из госзакупок РК.

## Проблема

В Bitrix24 клиента сделки по госзакупкам загружались тремя разными путями:
штатным XLS-импортом, старым скриптом и вручную. Результат:

- **70% строк очередной выгрузки оказывались дублями** — наивный импорт создал бы
  63 копии из 90 строк;
- у 4075 сделок не было машиночитаемого ключа источника — каждый новый импорт
  «не видел», что сделка уже есть;
- менеджеры звонили по одному тендеру дважды, воронка врала.

## Что сделали

1. **Идемпотентный импорт.** Каждая сделка получает ключ `ORIGIN_ID` из источника.
   Повторная заливка того же файла не создаёт ни одного дубля — только новые строки.
2. **Бэкфилл ключей на старые сделки.** 130 сделок старого XLS-импорта переведены
   под единый ключ автоматически (по ссылке на пункт плана). Конфликты не
   перезаписываются, а попадают в отчёт.
3. **Каскадный детект дублей до записи.** Если ключа нет, кандидат ищется по
   резервным признакам (ссылка, ID пункта, БИН + сумма) — и не создаётся.
4. **Карантин дублей.** Для 40 подтверждённых пар (старая копия + основная сделка)
   создана отдельная провальная стадия «Дубль»: копии убраны из активной воронки,
   основная сделка не тронута, история сохранена.
5. **Dry-run по умолчанию.** Ни одна операция не пишет в CRM без явного флага —
   сначала клиент видит полный отчёт «что будет создано/обновлено/пропущено».

## Результат (из логов)

```
до:    duplicate=63 из 90 строк выгрузки (наивный импорт задвоил бы 70% файла)
после: create=8  existing=82  duplicate=0  skipped=0  failed=0
```

- **4075 сделок** просканировано, **130** получили ключ идемпотентности;
- **40 пар дублей** найдено и заархивировано — `archived=40 failed=0`;
- **0 ошибок API** за все прогоны (троттлинг + автоповторы);
- менеджеры больше не звонят по одной закупке дважды, статистика воронки чистая.

## Почему это безопасно

- Любой запуск сначала идёт в режиме отчёта (dry-run), запись — отдельным флагом.
- Инструмент отказывается перезаписывать чужие ключи и двигать основные сделки.
- Все операции журналируются в JSON-отчёты — видно каждую изменённую сделку.
