# Д1: раскрывающиеся списки долгов менеджера

Дата: 10.11.2026. Ветка `feat/pult-debt-lists`, база — свежий `origin/main` (`c8d96aa`).
Все добавленные сценарии и примеры используют выдуманные сделки.

## RED

Сначала добавлены тесты, затем запущены без изменений реализации:

```sh
npx vitest run tests/bitrix/salesPultDebts.test.ts tests/bitrix/salesPultCollect.test.ts tests/bitrix/salesPultBrowser.test.ts --pool=forks
```

Результат: 11 ошибок, 64 теста прошли. Новых полей списков ещё нет;
кнопки «пора закрыть» отсутствуют, открытие других списков недоступно.
Проверены:

- Два новых дела одной сделки дают одну запись с возрастом старшего дела.
- Два passed-дела одной сделки дают одну сделку «пора закрыть».
- Сортировка: passed и won/partner по сумме, новые по возрасту,
  просроченные по дням; несколько просроченных дел одной сделки сохраняются,
  включая 30+ дней.
- Все четыре списка ограничены 50 записями при счётчике 60.
- Выигранная сделка в рабочей стадии попадает в список, стадии S/F исключены;
  дата подписания берётся из уже загруженного комментария.
- Кнопка открывает строку и нужный список мышью, Enter и Space;
  строка по-прежнему переключается обычным нажатием.
- Название с `<img src=x onerror="window.debtXss=1">` выводится текстом,
  картинка не создаётся и обработчик не выполняется.

## Решения

1. Списки — дополнительные поля `ManagerDebts`, необязательные для совместимости
   со старыми JSON и закрытыми месяцами. Сборщик заполняет их, пустые значения — `[]`.
2. Расчёты счётчиков, `readyToCloseDealIds`, топ задач и существующий список 30+
   сохранены. Новые списки сортируются и обрезаются независимо от счётчиков.
   Возраст нового дела округляется вниз до целых рабочих дней, как существующая
   метрика возраста; выбор старшего выполняется до округления.
3. «Пора закрыть» дедуплицируется по сделке; «без звонка» сначала сортируется
   по возрасту, затем дедуплицируется. Просроченные дела не дедуплицируются.
4. Выигранные сделки берутся из той же выборки шага 9 `collect.ts`;
   дополнительных запросов к Битриксу нет. Перед добавлением списка создаётся
   копия debts, чтобы не менять общий `EMPTY_DEBTS` при ошибке загрузки дел.
5. Нативные кнопки используют стандартную активацию Enter/Space. Обработчик
   строки пропускает события кнопок; повторное нажатие метки сохраняет строку
   открытой. Каждый список находится в своей строке `<details>` и использует
   отдельный `data-debt-list`.
6. Ссылки строятся из `P.portal` и ID сделки, открываются в новой вкладке.
   Названия и метаданные экранируются через `esc()`. Остаток отображается как
   «и ещё N в Битриксе». Сумма и возраст/дата расположены справа с переносом
   на узком экране.
7. Существующие ожидания тестов не изменялись. Добавлены проверки ширины
   1440/375 px, прежние тесты 30+, закрытых месяцев и ТВ сохранены.
8. Блок «Требует внимания», рынок, планы, реестр ОП и workflow не менялись.
   Генерация сайта на реальных данных и запись в Битрикс не выполнялись.
