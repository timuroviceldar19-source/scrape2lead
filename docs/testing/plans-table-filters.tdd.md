# Фильтры и сортировка открытых планов

## Границы

Этап 3. Ветка от свежего `origin/main` после слияния этапа 2.
Изменения относятся к открытой таблице планов и распознаванию названия

Все браузерные данные вымышлены; рабочие имена и суммы не используются.

## RED

Сначала добавлен `tests/bitrix/salesPultPlansFilters.test.ts`. На прежней реализации

## Решения

- `PlansGroupView.openPlans` содержит все открытые планы с `managerId` для
  точного фильтра менеджера. Массив существует только на уровне группы;
  в `monthViews`, в том числе `monthViews.all`, его нет.
- Ограниченные списки карточек менеджеров и заказчиков сохранены;
  `topOpenPlans` удалён из корня, месячных срезов, типов и клиента.
  Полный массив не передаётся
  в модель основного пульта (`VIEW`), в закрытые месяцы или в отдельный реестр.
- Сначала выбираем месяц, затем применяем четыре фильтра с логическим И:
  менеджер, вид товара, статус портала, способ закупки.
- Варианты фильтров берём из полного массива группы, поэтому сочетание может
  дать пустой результат. Для каждого фильтра есть кнопка «Все».
- Состояние фильтров и сортировки раздельно для ИП и КТ. Выбор месяца
  сохраняется при фильтрации и сортировке; фильтры и сортировка сохраняются
  в `sessionStorage` раздельно для ИП и КТ. Чтение, разбор и запись защищены
  `try/catch`. Исчезнувшие значения сбрасываются на «Все», лимит после загрузки — 50.
- Фильтрация и сортировка перерисовывают только таблицу и её управление.
  Итоги, графики и разбивки выше не пересчитываются.
- Клик по заголовкам суммы, месяца или количества переключает направление.
  При равенстве используется ID для стабильного порядка. Есть `aria-sort`,
  видимые стрелки и доступные с клавиатуры кнопки, в том числе на мобильном.
- Сначала показываем 50 строк, затем добавляем по 50. Смена месяца, фильтра
  или сортировки сбрасывает лимит. Без фильтров при пустой выдаче показывается
  «Открытых планов нет», с фильтрами — «Ничего не найдено».
- Фильтры стоят в разделе 04 перед таблицей, без липкости. До 760 px каждая
  группа кнопок занимает одну строку с внутренней прокруткой. После клика
  верх таблицы виден ниже липкой шапки. В ТВ и на других вкладках фильтров нет.
- Правило названия мультимедийной системы принимает оба порядка слов.

## Проверки браузера

На 1440 и 390 px проверяются обе группы, оба месяца, все 16 комбинаций
двух значений каждого из четырёх фильтров, три сортировки в обоих направлениях
(768 сочетаний сортировки с месяцем и фильтрами). Ожидаемый порядок строк
сравнивается с независимой выборкой исходных нормализованных данных.
Дополнительно проверены сортировка по месяцу и количеству без ограничения
месяца, первые 50/следующие 50 строк, неизменность итогов, сохранение месяца,
пустой результат, отсутствие кнопки продолжения при пустом результате,
обычное положение фильтров и отсутствие горизонтальной прокрутки страницы.

Проверены вход и выход из ТВ, основной пульт, Рынок ИП и КТ. Полная таблица
не рендерится в этих разделах. ТВ — режим того же `index.html`, поэтому
использует общий уже загруженный payload, без отдельной копии списка.
В HTML полного пульта ключ `openPlans` встречается ровно два раза (две группы),
в HTML отдельного реестра — ни разу. Сбор закрытых месяцев планов не запрашивает.

Скриншоты фильтров, отсортированной таблицы и пустой выдачи сохраняются вне
репозитория при запуске с `PLANS_SCREENSHOTS_DIR`. Они содержат только
вымышленные данные. Размер страницы записывается туда же в `page-size.json`.

### Решения и проверки

- Из `pult.html` удалён `#planFilters`, из `renderPlanMonths` — управление его
  видимостью. Фильтры входят в сам раздел 04 и исчезают вместе с ним.
- Состояние хранится в `sales-pult:plans:plans-ip` и `sales-pult:plans:plans-kt`.
  Сохраняются только фильтры и сортировка, без лимита строк. Проверены все четыре
  фильтра, разделение групп, прежний месяц в hash, сброс отсутствующих значений,
  повреждённый JSON и запрет доступа к хранилищу.
