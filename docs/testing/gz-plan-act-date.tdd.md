# Дата акта в HTML-карточке пункта плана

## Проблема

В текущей карточке портала дата акта находится в отключённом поле
`input` с `name`/`id="act_date_tmp"` под подписью «Дата акта, которым
утвержден (изменен) годовой план». HTML-резервный путь читал дату только
из прежних пар метка/значение, поэтому при недоступном API возвращал
`date_approved: null`, даже когда значение даты было в карточке.

Это дата акта заказчика, а не дата размещения или первого обнаружения
пункта роботом. Исправление не устанавливает причину задержки сбора.

## RED

Добавлен отдельный набор `tests/kz/goszakupPlanActDate.test.ts`:

- текущая форма портала с датами `2026-10-19` и `19.10.2026`;
- поиск поля по `id`, когда имя отличается;
- сохранение старых меток и их приоритета при наличии обоих форматов;
- отсутствие подмены даты акта датой публикации;
- пустое поле даты акта.

До исправления команда `npx vitest run tests/kz/goszakupPlanActDate.test.ts`
дала 3 ошибки и 4 успешных теста: все три случая заполненного `act_date_tmp`
возвращали `null` вместо нормализованной даты.

## GREEN

После существующего поиска по метке добавлено чтение `act_date_tmp`
через общий `extractControlValue`. Существующая нормализация даты
приводит обе формы к `YYYY-MM-DD`; прежние метки остаются приоритетными.

`npx vitest run tests/kz/goszakupPlanActDate.test.ts tests/kz/goszakupPlanParser.test.ts`
— 20 тестов успешно (7 новых и 13 существующих).

Дополнительно обработана сохранённая при исследовании реальная HTML-карточка
пункта 82545473 (запись 88303329): `date_approved` равна `2026-10-19`.
Полный `npm test` — 1172 успешных теста, 4 пропущены; сборка и проверка типов
завершились успешно. Новые запросы к порталу для проверки исправления,
запись в Bitrix и запуск боевого workflow не выполнялись.
