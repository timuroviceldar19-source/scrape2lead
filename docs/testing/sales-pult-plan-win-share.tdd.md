# Д2: доля побед на страницах «Планы ИП» и «Планы КТ»

10.11.2026. Ветка `feat/pult-plan-win-share`, база свежего `origin/main` —
`1f973ab` (после PR #117). Все новые имена, закупки и суммы выдуманы.

## RED

Сначала добавлен `tests/bitrix/salesPultPlanWinShare.test.ts`, реализация ещё
не менялась. Команда:

```sh
npm test -- tests/bitrix/salesPultPlanWinShare.test.ts
```

Оба браузерных сценария (1440 и 375 px) упали: в строке менеджера нет
`.plan-win-share`. Каждый сценарий проверяет обе страницы, а также:

- `9 / 22` → `29%`, ширина полоски `29%`;
- `1 / 0` → «мало итогов» без полоски;
- `0 / 10` → `0%` с полоской нулевой ширины;
- итог ноября: `10 / 32` → `24%`, по сумме `1000 / 6400` → `14%`,
  «из 42 с итогом»; открытые, отменённые и опубликованные исключены;
- октябрь: `4 / 1` → «мало итогов», «из 5 с итогом»;
- сентябрь: 10 побед при нулевых суммах → `100%`, по сумме `0%`;
- возврат ко всем месяцам → `42%`, по сумме `36%`, 57 итогов;
- сортировка менеджеров по сумме и раскрытие их открытых планов;
- порядок плиток 3 + 2 на компьютере, прежний первый readout;
- мобильные подписи «доля побед» и «выиграл … · проиграл …»,
  отсутствие горизонтального переполнения страницы.

## Решения

1. `WIN_SHARE_MIN_DECIDED = 10` общий для менеджеров и итога страницы.
   Округление — `Math.round`; знаменатель состоит только из won + lost.
2. И таблица, и плитка используют выбранный срез `V`. Payload, сборщик,
   агрегатор, сортировка и обработчики переключения месяца не менялись.
3. Полоска содержит уже округлённое значение, экранированное через `esc`;
   подписи чисел выводятся через `fmt`. Промежуточный GREEN обнаружил
   `28.999999999999996%` при повторном пересчёте общей функцией `bar`;
   теперь ширина прямо равна округлённому проценту (`29%`).
4. При нулевой сумме wonSum + lostSum доля по сумме равна `0%`;
   малое число итогов скрывает обе доли, но сохраняет число итогов.
5. CSS ограничен `.plans-summary`. Таблица получила шесть колонок;
   до 600 px новые ячейки занимают полную строку, доля подписана
   через `::before`, числа побед и поражений имеют видимый мобильный текст.
   На компьютере остаётся компактное «9 / 22».
6. Изменения production-кода только в `plans.client.js` и `pult.css`.
   Workflow, Битрикс, payload и настоящие данные не затрагивались.
