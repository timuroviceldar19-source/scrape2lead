# GZ: просроченный сертификат procurement.gov.kz — журнал TDD

## Откуда задача

21.11.2026 пользователь: «с 18 числа лоты не поступают в bitrix». Последний лот робота — сделка 57913 (18.11, 17:58 по
Алматы). С 19.11 03:40 UTC каждый запуск «GZ daily plans and lots» был зелёным, но в `manifest.json` стоял
`exportLots: failed` («источник полностью недоступен; ни один поисковый запрос не прочитан»), а `applyLots` не запускался.

Причина: сертификат `procurement.gov.kz` (RapidSSL TLS RSA CA G1, лист SHA-256 `5B:ED:DC:A0:…:4C:AD`) истёк
18.11.2026 в 23:59:59 GMT и не продлён. Портал при этом работает: объявление 18000853 опубликовано 21.11 в 18:53.
В логах GitHub — `net::ERR_CERT_DATE_INVALID` вперемешку с `net::ERR_CONNECTION_TIMED_OUT`; после трёх отказов подряд
предохранитель пропускал остальные 90 запросов. Probe писал `inconclusive: CERT_HAS_EXPIRED` и запускал робота. Задеты и
планы: контакты новых заказчиков читаются из реестра портала, 21.11 пропущено 8 строк `registry`.

Почему писем не было: `net::ERR_CERT_*` подходит под сетевой шаблон `net::ERR_`, поэтому сбой считался временной
недоступностью. Ветка лотов изолировалась, планы записывались, `automation run` выходил с кодом 0.

## Решение

1. **Доверие ровно к ключу портала** (`src/kz/gzPortalTls.ts`). Chromium запускается с
   `--ignore-certificate-errors-spki-list=<SHA-256 SPKI>`: ошибка сертификата пропускается, только если в цепочке есть
   сертификат с этим открытым ключом. Другой просроченный, самоподписанный или поддельный сертификат отклоняется.
   Подделать сертификат с этим ключом может только владелец закрытого ключа портала. Когда портал продлит сертификат,
   проверка снова проходит обычным путём. Портал отдаёт один сертификат с одного адреса (149.170.62.13, проверено
   8 подключениями), поэтому одного ключа достаточно.
   Через `gzPortalLaunchOptions` идут все запуски браузера для портала: лоты (`goszakupLotsNstruExporter`), реестр
   заказчиков (`goszakupRegistryCollector`), БИН организатора при записи лотов (`bitrix-push-gz-lots.mts`), планы портала,
   договоры и два ручных скрипта номеров планов.
2. **Ошибка сертификата не тихая.** `isCertificateError` в `src/kz/gzCollection.ts`. Сбор по-прежнему изолирует её в своей
   ветке (планы записываются), но этап получает `certificateErrors`, в Summary строка «Ошибка сертификата портала», а
   `automation run` в конце выходит с кодом 3. `run-automation-with-retry.sh` возвращает 3 сразу, без повторов через
   10 минут, шаг workflow падает, приходит письмо.

Node `fetch` исключения не получил: в ежедневном сборе на портал через Node ходит только probe, а он при ошибке
сертификата пишет `inconclusive` и запускает робота.
