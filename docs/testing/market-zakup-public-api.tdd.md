# TDD: рынок из открытого API zakup.gov.kz, ows — запасной

## Зачем
- 29.10.2026 токен `GOSZAKUP_TOKEN` перестал работать: `ows.goszakup.gov.kz/v3` на любой запрос с ним отвечает `403 Access denied`, так же как на выдуманный токен. Без токена ответ `401`, то есть отказ относится к токену, а не к IP.
- Кроме того, ows с IP GitHub днём приступами не отвечает (`fetch failed`, таймаут соединения).
- Сайт Единой платформы закупок `zakup.gov.kz` берёт данные с открытых адресов `https://zakup.gov.kz/api/core/api/public/...` без токена. В базе есть и история старого портала (`system_id=1`, ЭГЗ).

## Что проверено руками (29.10)
- Список договоров `/public/contracts/`: фильтры `sign_date__gte/__lte`, `system_id`, `enstru_code__startswith` (по началу кода), страница не больше 100 записей (`limit`/`offset`; `page_size` даёт 400).
- `external_id` договора = id договора в ows. 78 из 78 октябрьских договоров F3 в кэше рынка нашлись по нему.
- Позиции договора `/public/contracts/{id}/subjects/`: `item_price_without_vat` совпадает с `itemPrice` из ows (договор 26049747: 1 077 586), код ЕНС ТРУ — в `plan_item.enstru.code`.
- БИН поставщика и заказчика есть только в карточке договора `/public/contracts/{id}/` (`supplier_organization.iin_bin`, `customer_organization.iin_bin`). Поиск организаций сразу по нескольким id API не умеет, поэтому БИН кэшируется в `data/market/orgs.json` (id → БИН).
- В справочниках `/dicts/contract-statuses/` и `/dicts/purchase-methods/` у записей есть `egz_code` — код старого портала. Через него работают прежние `excludedStatuses` и названия способов из `config/market-monitor.json`.
- С IP GitHub (прогон 40917884404, 17:05 UTC): zakup ответил на 25 запросов из 25, ows в тех же заходах — на 2 из 5.

## Сверка с кэшем (октябрь 1–29), первый круг
- 1266 общих договоров совпали по сумме, БИН, способу и дате. Расхождения нашлись двух видов, оба стали тестами:
  - 211 договоров с завышенной суммой: часть позиций платформа загрузила дважды — тот же `external_id` позиции, разница в `timestamp` около секунды. Позиция с одним старым id теперь берётся один раз (последняя копия).
  - 22 договора есть только в кэше: у них пустой общий `enstru_code` (код есть только в позициях), поэтому поиск по префиксу их не видит. Пример — 25970383 на 16,5 млн. Добавлен отдельный список `enstru_code__isnull=true` + `purchase_subject_id=1` (товары): в октябре это 458 договоров.
- Договоры «только в zakup» почти все подписаны 28–29.10, после того как кэш обновлялся утром.

## Сверка, второй круг (после правок)
- Общих договоров 1479: 1469 совпали полностью, у 10 сумма отличается на копейки или на размер НДС/допсоглашения. БИН, способ и дата совпали у всех.
- ИП: кэш 94 договора / 231,1 млн, zakup 99 / 261,3 млн. КТ: 1405 / 2413,1 млн против 1431 / 2426,0 млн. Разница — договоры 28–29.10, которых в утреннем кэше ещё не было.
- 20 договоров (1,3%) остались только в кэше: на платформе у них нет кода ЕНС ТРУ ни в договоре, ни в пункте плана, ни в лоте (например, 26074371 — «Панель интерактивная», 1,7 млн). Определить группу по открытому API нельзя; если платформа заполнит коды позже, договоры попадут в рынок при следующем обновлении.
- Скорость: октябрь (29 дней) — 2748 запросов за 178 с с пустым кэшем БИН и 2021 запрос за 127 с с заполненным (1432 организации, 33 КБ).
