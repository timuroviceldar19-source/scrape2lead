# Быстрый отказ GZ при недоступности портала с машины GitHub

Дата: 09.11.2026. База: свежий `origin/main`, `274dfca8910081d1ad20e52ce3f536d49701125d`
(актуальность проверена через GitHub API). Ветка: `fix/gz-portal-probe`.

## RED

До реализации добавлены `tests/kz/gzPortalProbe.test.ts` и два сценария обёртки:
постоянный отказ проверки и отказ с последующим успехом. Запуск
`npx vitest run tests/kz/gzPortalProbe.test.ts tests/automation/runAutomationRetry.test.ts`
дал два упавших файла: модуль проверки отсутствовал, обёртка запускала automation
без проверки (два новых сценария красные, пять прежних зелёные).

Отдельно добавлен и запущен `tests/automation/gzRunSummaryCli.test.ts`: красный,
сводка выбирала старый манифест `OLD-CACHED`, несмотря на отказ проверки.

## GREEN и решения

- `src/kz/gzPortalProbe.ts`: адрес через существующий `buildPlanSearchUrl`, GET,
  общий дедлайн 20 секунд на получение ответа **и чтение тела**, до трёх попыток,
  пауза 10 секунд только между отказами. AbortController отменяет запрос,
  Promise.race ограничивает также зависший fetch/text. Первый успех завершает probe.
- HTTP проверяется существующим `assertPortalResponse`. Его строгий отказ на
  403/404 здесь допускается: ответ ниже 500 (кроме 429) означает доступность машины.
  HTML всегда проходит `assertPortalHtmlAvailable`; 429, 5xx, техработы — отказ.
  Общие guards и GzCollectionState не менялись.
- Сетевые исключения классифицируются `isTransientNetworkError`; в строке
  сохраняются name, message и code цепочки cause, включая ENOTFOUND/ETIMEDOUT.
  Неожиданные исключения передаются наружу; тонкий CLI возвращает для них код 2,
  для недоступности — 1, для успеха — 0. CLI печатает одну итоговую строку.
- Обёртка перед каждой попыткой пишет вывод probe в LOG. При коде 1 automation
  не запускается, действуют прежние ATTEMPTS/PAUSE. При коде 2 повторов нет.
  Проверка не входит в участок лога, по которому классифицируется ошибка automation:
  прежний сетевой отказ probe не должен скрывать последующую ошибку кода.
- При полном отказе всех проверок итоговый код 1 и строка
  «портал недоступен с этой машины GitHub, прогон не начинался».
  Если хотя бы одна попытка automation начиналась, это утверждение не выводится.
- Состояние пишется рядом с LOG (`.portal-probe-state`), с ключом
  GITHUB_RUN_ID:GITHUB_RUN_ATTEMPT. Сводка получает путь LOG дополнительным аргументом
  в reusable workflow, узнаёт отказ текущего job и не читает кэшированный manifest.
  Состояние другого job/повтора игнорируется. Исключения сводки по-прежнему ловятся.
- Guard, watchdog, daily workflows, gz-probe.yml, расписание Worker, concurrency,
  таймауты/повторы страниц и Bitrix не менялись. Отказ остаётся красным job.

Покрытие без сети:

- Probe: HTTP 200/403/404, fetch failed с cause ENOTFOUND/ETIMEDOUT,
  TimeoutError, 503/429, техработы, число попыток, паузы, первый успех,
  неизвестная ошибка без повтора, зависший fetch и зависший text (fake timers).
  Строки unreachable проверяются регулярным выражением NETWORK_PATTERN,
  прочитанным из самой shell-обёртки.
- Обёртка: изолированные подставные npx/probe и run-automation.sh;
  RETRY_PAUSE_SECONDS=0. Полный отказ (0 запусков), отказ→успех (1 запуск),
  успех→несетевая ошибка (без повтора), успех→сетевая ошибка (повтор),
  исчерпание попыток, старые строки лога, неизвестная ошибка probe.
- CLI сводки: старый кэш при отказе проверки, старый marker другого job,
  реально начавшийся прогон, испорченный marker/manifest без падения сводки.

## Итоговая проверка

- Целевые тесты плюс `gzGithubWorkflow.test.ts`: 42 теста прошли
  (39 в совместном запуске, затем расширенная сводка 4 вместо 1).
- `npm run lint`: PASS.
- `npm run build`: PASS.
- `git diff --check`: PASS для кода перед оформлением журнала.
- Полный `npm test` выполнен: 1888 PASS, 10 FAIL, 25 SKIP;
  159 файлов PASS, 8 FAIL, 3 SKIP. Падения ограничены окружением:
  Chromium запрещён macOS sandbox (`bootstrap_check_in ... Permission denied`),
  отсутствует команда `python` и ReportLab.
- Для сравнения выполнен полный `npm test` в отдельном чистом worktree **точно
  на 274dfca** с теми же зависимостями: 1869 PASS, те же 10 FAIL, 25 SKIP;
  157 файлов PASS, те же 8 FAIL, 3 SKIP. Новых падений нет.
  CI репозитория сам устанавливает Chromium, Python и ReportLab.
  Локальный полный набор не выдаётся за зелёный и его проверки не ослаблялись.
- После завершения проверок локальная среда стала недоступна; проверенные тексты
  кода и тестов перенесены через GitHub API, журнал оформлен при передаче.

Ручные workflow не запускались. Запросы к порталу и запись в Bitrix для проверки
не выполнялись. PR предназначен для ревью, без merge.
