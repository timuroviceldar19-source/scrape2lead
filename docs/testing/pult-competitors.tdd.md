# TDD и сверка этапа 1: вкладка «Конкуренты» (`pult-competitors`)

## 1. Обзор реализации

Вкладка **«Конкуренты»** (рядом с «Рынок» в [`pult.html`](../../src/bitrix/salesPult/page/pult.html), [`reg.html`](../../src/bitrix/salesPult/page/reg.html) и [`site.ts`](../../src/bitrix/salesPult/site.ts)) показывает аналитику по открытым конкурсам Госзакупок (`method_id = 2`, способ «Открытый конкурс») по группам **ИП** и **КТ** из [`config/market-monitor.json`](../../config/market-monitor.json) (за исключением `hiddenKinds`, например `Мультимедийные системы`), начиная с `2026-01-01`.

В варианте менеджера ([`variants/manager.ts`](../../src/bitrix/salesPult/variants/manager.ts)) раздел скрывается и данные `payload.competitors` вырезаются из выгрузки.

### Архитектурные решения и выбор источника

1. **Источник данных — `procurement.gov.kz` + `v3bl.goszakup.gov.kz`**:
   - Публичный API `zakup.gov.kz/api/core/api/public/lots/` проверен вживую и признан неполным для открытых конкурсов 2026 года: для `enstru_id=29624` (`262030.100.000021`) возвращает лишь 57 лотов вместо 200 на портале, `/public/lots/{id}/` отдаёт `HTTP 500`, а вложения и заявки не экспонируются. Справочник `/dicts/enstrus/` периодически возвращает `HTTP 503` (реализован быстрый фоллбэк на встроенный перечень 55 активных кодов ЕНС ТРУ из `config/market-monitor.json`).
   - Авторизованный `ows.goszakup.gov.kz` токен при проверке возвращал `403`, поэтому коллектор работает полностью по публичному HTML-порталу `procurement.gov.kz` и `v3bl.goszakup.gov.kz` с корневым сертификатом `NODE_EXTRA_CA_CERTS=certs/rapidssl-tls-rsa-ca-g1.crt`.
2. **Последовательный поиск с проверкой маркеров ответа**:
   - При параллельных запросах `procurement.gov.kz/ru/search/lots` периодически отдаёт `HTTP 200` без таблицы `#search-result` (временная заглушка ~2 КБ) и HTML5-разметку с опущенными закрывающими тегами `</td>`.
   - Парсер [`htmlDom.ts`](../../src/kz/competitors/htmlDom.ts) поддерживает опущенные закрывающие теги, а [`discoverCompetitorLots`](../../src/kz/competitors/collector.ts) ходит по страницам поиска последовательно (`pauseMs = 550`), проверяет маркеры таблицы/пагинации и повторяет запрос с экспоненциальной паузой.
3. **Задел под этапы 2 и 3**:
   - Движок сопоставления шаблонов [`specTemplates.ts`](../../src/kz/competitors/specTemplates.ts) (`matchSpecTemplates`, `summarizeTemplateWinners`) загружает определения из `data/spec-templates.json` (не в репозитории, см. раздел 5).
   - Полные нормализованные тексты техспецификаций (PDF через `unpdf`, DOCX/XLSX/ZIP через `adm-zip`, DOC) сохраняются локально в таблице `techspecs` SQLite-базы (`data/competitors/competitors.db`) с методом [`CompetitorsStorage.searchTechSpecs`](../../src/kz/competitors/storage.ts) для будущего поиска произвольной фразы (этап 3). В репозиторий `data/competitors/` не коммитится (кэшируется через `actions/cache@v4`).

## 5. Шаблоны ТС вне репозитория

- **Решение (16.11.2026):** тексты шаблонов — это куски ТС заказчиков, а репозиторий публичный. Поэтому `config/spec-templates.json` и `config/spec-templates/*.txt` убраны.
- **Где лежат шаблоны:**
  - локально — `data/spec-templates.json` (`data/*` в `.gitignore`);
  - в GitHub — секрет репозитория `SPEC_TEMPLATES`. Шаг `Spec templates from secret` в `sales-pult.yml` пишет его в тот же файл, содержимое в лог не попадает;
  - другой путь можно задать через `SPEC_TEMPLATES_PATH`.
- **Формат:** тот же JSON, текст шаблона внутри поля `text`, поэтому файл целиком помещается в секрет.
- **Если секрета нет или JSON битый:** предупреждение `::warning::`, блок «Шаблоны ТС» пустой, остальная сборка идёт как обычно.
- **Совпадения пересчитываются при каждой сборке** по сохранённым текстам ТС из кэша (`rebuildNormalizedFromStorage`). Поэтому новый шаблон в секрете сразу находит и старые лоты.
- **Тесты:** работают на выдуманном шаблоне `tests/fixtures/kz/spec-templates.demo.json`.
  - RED: `keeps techspec template texts out of the public repository` падал, пока в `config/` лежали шаблоны.
  - Для шага workflow отдельный тест: секрет пишется в файл, текст не печатается, без секрета и с битым JSON сборка остаётся зелёной.

- **Что случилось (16.11.2026).** Ручной запуск с `competitors_backfill_from=2026-01-01` (run 43903145909) упал по таймауту задачи, 240 мин:
