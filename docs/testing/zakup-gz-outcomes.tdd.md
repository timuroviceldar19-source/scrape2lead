# Итоги сделок: открытый API zakup

Задача: итоги и статусы без обязательного GOSZAKUP_TOKEN. Секреты и данные CRM в репозиторий не включаются.

## Решения

- Сначала zakup, при ошибке и заданном токене — ows. Успешный пустой ответ не включает резерв. При двух ошибках сохраняются обе причины.
- Год переводится через `/dicts/years/`, БИН — через общий `data/market/orgs.json`, обратный поиск по значениям.
- Позиции договора проходят `dedupeSubjects`; `plan_item.external_id` — версия, `root.external_id` — номер пункта. Сумма берётся без НДС.
- Поиск корня: `plan-items/?q=...`, обязательное совпадение БИН и год не раньше сделки. Если результата нет — позиции договоров заказчика и точная связь `root.external_id`. Карточки и договоры кэшируются в памяти одного прогона.
- HTML остаётся в существующем резерве скрипта. Новый основной HTML-поиск отменён после уточнения задачи.
- Названия статусов берутся из справочников/карточек ЭГЗ с непустым `egz_code`. Правила решений не меняются.
- `is_externally_deleted`, если присутствует, переводится в `deleted`. Публичная карточка договора в исследованном ответе этого поля не содержит; полную эквивалентность старому флагу удаления подтвердить нельзя. Статус расторжения удалением не считается.
- `timestamp` не используется как доказанная дата создания версии. Для проверки возраста товара берётся консервативная дата акта; без неё правка товара запрещена.

## Проверки и локальные свидетельства

Вывод хранится вне Git: `F:\Temp\zakup-migration-evidence`.

| Проверка | Команда | Вывод |
|---|---|---|
| RED: отсутствующий адаптер договоров | `npx vitest run tests/kz/zakupGzRegistry.test.ts` | `outcomes-red.txt` |
| GREEN: преобразование договора, дублей и выбор источника | та же команда | `contracts-green.txt` |
| RED: токен обязателен в CLI | `npx vitest run tests/automation/gzZakupSources.test.ts` | `cli-red.txt` |
| RED: обязательный секрет workflow | `npx vitest run tests/automation/gzGithubWorkflow.test.ts` | `workflow-token-red.txt` |
| Поиск q на сохранённой выборке со статусом | `node --import ./tmp/zakup-readonly.mjs --import tsx tmp/validate-zakup-q.mts` | `q-sample.txt`, `q-sample-summary.json` |
| Резерв через договоры той же выборки | `node --import ./tmp/zakup-readonly.mjs --import tsx tmp/validate-zakup-q-contracts.mts` | `q-contracts.txt`, `q-contracts-summary.json` |

Скрипты сверки в `tmp/` локальные, не входят в публичный репозиторий. Наличие старого статуса в CRM само по себе не доказывает время его записи: утверждать, что каждое отличие произошло после утреннего обновления, нельзя без дополнительного свидетельства.
