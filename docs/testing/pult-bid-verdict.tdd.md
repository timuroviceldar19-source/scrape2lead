# Пульт F3: вердикт «идём / осторожно / не идём» на сервере (пункт 5 RFC)

21.11.2026 · ветка `feat/pult-bid-verdict` от `origin/main` `5bcb7aa`.

## Что сделано

- Подсказки «как выиграть» больше не считаются в браузере. Индексы «покупал у нас», «кому проигрывали»,
  «шаблон ТС», «цена побед» перенесены из `page/plans.client.js` в `src/bitrix/salesPult/bid/assess.ts` без
  изменения правил. Пороги 115% и 90% остались прежними.
- К ним добавлены:
  - прошлые отклонения наших заявок у заказчика — по категории причины (`classifyRejectionReason`), без текста протокола;
  - вердикт;
  - ценность = сумма × вес вердикта (`BID_VALUE_WEIGHTS`: идём 1, осторожно и без вердикта 0,5, не идём 0,1).
- Источники проверяет zod (`bid/sources.ts`). Битая запись пропускается и считается, отсутствующий раздел считается
  нормой. В лог сборки идёт только строка `[Вердикт] ИП: идём N, осторожно N, не идём N, без вердикта N; КТ: …`.
- `bid` ставится у карточек Радара (кроме пропущенных сроков) и у открытых планов. Это делает
  `renderPultHtmlWithView` из того же payload, что уходит в страницу. Поэтому вердикт не может опереться на данные,
  которых нет в странице роли.
- Браузер только рисует: `page/bid.client.js` (плашка, метки, строка цены). На Радаре появился порядок
  «по сроку / по ценности». Он показывается, только если вердикты вынесены.

### Правило вердикта

- Нет данных «Конкурентов» по группе или нет ни одного сигнала — `unknown`, плашки нет.
- ТС этого лота сильно совпадает с шаблоном, где чаще побеждал конкурент, — «не идём».
- Остальное считается баллами:
  - плюсы: покупал у нас +2, точная цена с запасом +1, шаблон с нашими победами +1;
  - минусы: точная низкая цена −1, конкурент забирал заказчика −1 (от 3 раз −2), шаблон конкурента в этом лоте −2,
    тот же шаблон у заказчика раньше −1 (сильный −2), нас отклоняли у заказчика −1 (от 2 раз −2);
  - минусов нет — «идём», итог ≤ −3 — «не идём», иначе — «осторожно».
- Шаблон, где чаще побеждала наша компания, теперь зелёная метка и плюс, а не риск. Быстрый фильтр
  «Риск ТС / конкурента» в «Планах» его больше не считает.

### Роли

- **all:** вердикт, метки, порядок «по ценности».
- **manager:** в его payload нет «Конкурентов» (умолчание по вопросу 3 RFC), поэтому вердикт не выносится. Остаются
  метки и цена из его «Планов» и всего «Рынка», как раньше в браузере. Иначе лот «не идём» у директора выглядел бы
  у менеджера как «идём».
- **tv:** Радар и «Планы» в режиме ТВ не открываются (`setTab` возвращает на главную). Плашка дополнительно скрыта
  `body.tv .bid-verdict`.

## Проверка на настоящих данных (локально, сборка 17.11, только счётчики)

Первый замер: +307 КБ к 10,55 МБ payload, 1 283 вердикта, расчёт ~100 мс. В ИП «не идём» вышло у 102 из 340 позиций.
Разбор показал, что 92 из них — «конкурент забирал + низкая цена» в открытых планах, а «низкая цена» стояла
у 39 из 46 лотов Радара ИП. Это старая ошибка браузерных подсказок:
- у панели без диагонали ориентиром была строка «Конкурентов» «Панель диаг. не указана» с выборкой из одного лота (n=1);
- по ней сравнивались 298 позиций ИП, медиана отношения цены к ориентиру была 0,49.

Исправление (`bid/assess.ts`):
- ориентир берётся только из выборки от 3 побед (`BID_PRICE_MIN_SAMPLES`);
- у панели без диагонали и у учебного комплекта медиана вида — справка без цвета, на вердикт она не влияет;
- справочная цена сама по себе не сигнал;
- вес точной низкой цены снижен с −2 до −1.

RED: новые тесты блока «ориентир цены побед» со старыми правилами (порог 0, без грубых видов, вес −2) — 5 failed.
GREEN: 17 passed.

После правки: ИП — идём 176, осторожно 147, не идём 8, без вердикта 9; КТ — идём 421, осторожно 502, не идём 20.
В КТ «не идём» в основном у «второго шанса» с низкой ценой; для несостоявшейся закупки это реальный сигнал.
Цена: +285 КБ (~2,7%).

## Что не сделано

- Вердикт менеджеру — ждёт ответа на вопрос 3 RFC (можно ли показывать подсказки «Конкурентов»).
- KPI «подачи при вердикте „не идём“» пока не считается: нужен снимок вердиктов на день подачи. Строка лога
  `[Вердикт]` даёт базу по дням.
- Сортировка «по ценности» в таблице «Планов» не добавлялась: там свои сортировки по сумме, месяцу и количеству.
