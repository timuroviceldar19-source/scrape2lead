## Гарантии

оперативные периоды остаются предварительными по CRM. Реальные выгрузки и результаты
сверки хранятся только локально и в отчёте пользователю. Здесь только выдуманные данные.

## Решения и ограничения

- Пульт получает только агрегаты реестра; себестоимость, валовая прибыль и премии
  в новый контрактный источник не попадают. Сопоставление использует уже загруженные
  названия компаний CRM без дополнительной гидратации для каждого менеджера.
- Закрытые CRM-кэши инвалидированы версией расчёта, чтобы старые WON/lost не оставались
  в истории. Агрегаты ОП накладываются после чтения кэша, поэтому новый файл ОП виден сразу.
- История ОП теперь сохраняет дневные договоры и выручку. Старый зашифрованный кэш
  без дневных точек показывает явное сообщение о недоступной дневной разбивке;
  после штатного обновления истории график появится. CRM-график не выдаётся за ОП.
- При ошибке текущего файла сохранённая история ОП остаётся доступной для закрытых месяцев.
- D1/D2 — подсказки проверить сопоставление, а не доказательство ошибки менеджера:
  matcher эвристический и один-к-одному; товарные сделки и дубли автоматически не склеиваются.
- Сигналы текущего периода не выводятся на странице закрытого месяца. Противоречие
  WON/lost загружается независимо от даты перехода, пока не исправлено в CRM.
- Чат-отчёты намеренно не переведены на ОП: утренний содержит нормативы без факта,
  вечерний использует оперативные CRM day/week/month роллапы. Отправка выключена.
  Подключение ОП к вечернему месяцу потребует отдельного изменения загрузки этих режимов;
  подтверждённый месячный источник в этой задаче — пульт. Исключение предусмотрено пунктом F задания.
- `npm audit` выполнен: найдены существующие уязвимости зависимостей. Lockfile и зависимости
  не менялись; автоматическое обновление с несовместимыми версиями не выполнялось.

## Артефакты

Снимки полностью выдуманного сценария создаются браузерным тестом в игнорируемой папке
`exports/pult-contracts-fixture/`: current-month, tenders-month, closed-month, signals.
Локальный прогон site выполнялся без execute. Публикация, запись в CRM, ручной запуск
боевых workflow и merge не выполнялись.

## Поправки после ревью

Проверка на настоящих данных за закрытый месяц (как если бы он был текущим) показала,
что примерно половина сигналов D1/D2 и строка «ждут ОП» — шум. Причины и поправки:

- **Сделки по товарам одного договора.** Matcher один-к-одному: договор ОП забирает одну
  сделку, остальные сделки того же договора оставались «нет в ОП». Теперь сделка того же
  заказчика и менеджера считается частью договора, пока сумма всех его сделок не больше
  суммы ОП с НДС и допуском (`settleUnmatched`). Без этого предела в договор попадали и
  сделки в несколько раз дороже — настоящие расхождения.
- **Дубли.** Сделка с суммой договора того же заказчика, уже учтённого по другой сделке
  или записанного в ОП на другого менеджера, выводится серым «Возможен дубль» с менеджером
  из ОП и не входит в «ждут ОП». Сделки не склеиваются.
- **B2B.** Сделки B2B пульт по Битриксу не считает, поэтому договоры B2B больше не дают
  «Есть в ОП, нет сделки в Битриксе». Договор, к которому есть сделка того же заказчика
  с другой суммой (например, нулевой), тоже не считается договором без сделки — для неё
  остаётся сигнал «Сумма сделки 0».
- **Порядок.** Сигналы ОП раскладываются по цветам: красные и жёлтые идут вместе со
  срочными, серые «проверить» — в конце списка.
- **Начало месяца.** Пока последний файл ОП за прошлый месяц, подпись — «файла ОП за
  <месяц> ещё нет, цифры по Битриксу», а не «реестр ОП недоступен».
- **Строка суммы** в блоке 01 без двойного разделителя, когда цифры по Битриксу.
