# Обновление Рынка: сохранение договоров без кода

Все номера, суммы и названия в тестовых примерах вымышлены.
Результаты проверки реального снимка сообщаются только в чате и не публикуются здесь.

## RED

Сначала добавлен `tests/kz/marketRefreshKeepsContracts.test.ts`.
Первый запуск: 9 красных тестов, 1 зелёный. Отсутствовал результат с `keepContractIds`,
строки без номера отбрасывались до чтения карточки, старые позиции исчезали из окна.

## GREEN

- `candidates` больше не отбрасывает строку из-за отсутствующего `external_id`.
  Если предмет классифицирован, номер берётся из списка либо из карточки.
  Одна карточка используется и для номера, и для БИН, включая случай уже закэшированных БИН.
  Если номера нет и там, договор пропускается и увеличивает отдельный счётчик.
- Договор с подходящим статусом, без классифицированных предметов, но хотя бы с одним
  неизвестным кодом либо без предметов передаёт номер в `keepContractIds`.
  Исключённый статус, полностью известные чужие коды и наличие классифицированного
  предмета не приводят к удержанию старых позиций.
- После выборки по широким префиксам список кандидатов ограничивается статусом,
  а не точным кодом строки списка. Иначе неизвестные коды предметов не были бы прочитаны.
  Дополнительный тест этого случая сначала падал, затем прошёл после удаления раннего фильтра.
- В окне сохраняются все прежние позиции из `keepContractIds`, только если свежих
  позиций этого договора нет. Свежий договор заменяет весь прежний набор в окне,
  даже при смене кода, цены, количества или индекса позиции. Отсутствующие в обоих
  списках договоры из окна удаляются; данные за границами окна сохраняются.
- Пример: договор 501 с двумя прежними позициями удерживается целиком при отсутствии кода.
  Если пришла новая позиция на 800 000 вместо прежних двух по 300 000, остаётся только новая.
  Договор 502 без свежих данных и без разрешения на удержание удаляется.
- Результат протянут через `fetchMarketUnits` в утреннее обновление и помесячную
  загрузку `backfillMarketByMonths`. Запасной источник ows не создаёт список удержания.
- Ошибки предметов и карточек не превращаются в пустой результат или пропущенный договор.
  Ошибка источника передаётся наверх; существующий механизм полноценного запасного
  источника сохраняется. Если выгрузка не завершена, запись окна не выполняется.
  Два теста ошибок проверяют неизменность байтов файла кэша после отказа API.
- После сохранения окна выводятся только количества: строк без номера в списке,
  договоров без кода, удержанных и ушедших из окна, пропущенных без номера.
  Сообщения об ошибках источников не печатают ответы API, URL карточек, номера,
  имена или суммы. Отдельный тест проверяет точный безопасный текст счётчиков.

## Проверки

```sh
npx vitest run tests/kz/marketRefreshKeepsContracts.test.ts tests/kz/marketZakupFetch.test.ts tests/kz/marketBackfill.test.ts
npm run lint
npm test
```

Полный набор: 164 файла прошли, 3 пропущены; 1873 теста прошли, 4 пропущены.
Проверка типов прошла. Для теста PDF использован доступный Python с ReportLab.

`config/market-monitor.json` и ключ конфигурации не меняются. Боевой кэш не переписывается.
Реальная проверка выполняется отдельным скриптом вне репозитория на копии исходных файлов
релиза с записью результата в отдельную папку. Bitrix, workflow и ручной backfill не запускаются;
разовое восстановление утраченных данных в этот этап не входит.
