# Полный обход выдачи планов ГЗ

## Проблема

Сбор планов ограничивался 50 страницами на ключевое слово. `Math.min` скрывал
усечение выдачи: запуск мог завершиться успешно, не обработав оставшиеся страницы.

## RED

`npx vitest run tests/kz/gzPlanCompletePagination.test.ts` — 6 ошибок до правки:

- запись 2501 на 51-й странице не собиралась;
- явный предел страниц возвращал неполную выборку без ошибки;
- неожиданно пустая промежуточная страница не отклоняла неполный сбор;
- обход до последней страницы и значение «все страницы» не поддерживались;
- конфигурации по умолчанию сохраняли предел 50;
- некорректное значение переменной окружения не валидировалось.

## GREEN

`maxPages: 0` — полный обход по количеству записей, объявленному порталом;
это значение установлено по умолчанию и в обоих автоматических конфигах планов.
Явный положительный предел теперь вызывает ошибку, если он обрежет выдачу.
Непредвиденно пустая промежуточная страница не возвращает уже собранный префикс.
Число страниц рассчитывается по общему количеству записей и `count_record`,
чтобы однобазовые ссылки портала не добавляли фиктивную последнюю страницу.

`npx vitest run tests/kz/gzPlanCompletePagination.test.ts tests/kz/goszakupPlanActDate.test.ts tests/kz/goszakupPlanParser.test.ts tests/kz/gzPlansConfig.test.ts`
— 48 успешных тестов после двух дополнительных регрессий из проверки изменений:
однобазовые ссылки без текста общего количества и нестандартный `count_record`.
Оба дополнительных теста воспроизводили ошибку до исправления.

`npm run lint`, `npm run build` и `git diff --check` завершились успешно.
Полный `npm test` — 1172 успешных теста, 4 пропущены (109 файлов успешно,
3 пропущены). Для независимых тестов КГД локально установлен Chromium и
использовано отдельное Python-окружение с ReportLab 4.5.1; зависимости проекта
и lock-файл не менялись.

## Границы

Тесты используют локальные HTML-страницы с 2501 записью. Боевой сбор, загрузка
в Bitrix и изменение расписания не выполнялись. Ограничение в этой правке
относится к планам, конфигурации лотов не меняются. Большая выдача требует
больше времени; изменения реестра во время обхода не дают атомарного снимка.
Отсутствие даты публикации или истории первого обнаружения эта правка не устраняет.
