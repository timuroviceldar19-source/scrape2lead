# TDD: «Рынок ИП» — только интерактивные панели

## Контекст и решение

С 01.11.2026 в группу ИП входил весь код ЕНС ТРУ `279020.100.*` («Панель жидкокристаллическая») как отдельный вид «Жидкокристаллические панели». Под этим кодом закупаются обычные мониторы, видеостены, LED-экраны и цифровые табло, что искажало аналитику пульта и завышало рынок более чем в два раза.

**Решение руководителя:** позиция с кодом `279020.100.*` учитывается в рынке, только если в описании есть слово «интерактивная» («интерактивті», «interactive»). Отдельный вид «Жидкокристаллические панели» убирается, прошедшие фильтр позиции считаются как «Интерактивные панели».

## Правило

- Код `279020.100.*` требует текстовый фильтр `textPatterns: ["интерактив", "interactive"]` (регистр не важен).
- Текст позиции составляется из `name_ru`, `extra_description_ru` и `extra_description_kk` (казахское «интерактивті» входит по префиксу «интерактив»).
- Если текста нет или слова нет — позиция исключается из рынка.
- Коды `262030.*` и вся группа КТ текст не требуют и работают как прежде.
- В источнике zakup текст берётся из `plan_item` позиций договоров.
- В источнике ows запрашивается `Plans { nameRu extraDescRu extraDescKz }`; позиции ЖК без описания пропускаются с логом `[Рынок] ows: N позиций ЖК без описания пропущено`.

## Доработка: получение описаний из ows для не найденных на zakup договоров

### Контекст

При первичной фильтрации 271 из 630 ЖК-договоров были удалены без чтения описания, так как не нашлись в поиске по префиксу на zakup (у старых договоров код ЕНС ТРУ часто отсутствует на уровне заголовка договора).

Описания этих договоров сохранились в ows v3 GraphQL:
- Запрос `Contract(filter: { id: [<номера ows>] }, limit: 50) { id ContractUnits { refEnstruCode Plans { nameRu extraDescRu extraDescKz } } }` отвечает по всем 630 договорам.
- Порядок `ContractUnits` совпадает с `unitIndex` в файле кэша.

Источники дополняют друг друга:
- ows содержит описания за январь–март (с апреля `Plans` чаще `null`);
- zakup содержит описания в основном с апреля.

### Правило

1. Описание ЖК-позиции берётся сначала с zakup.
2. Если договор на zakup не найден или у позиции пустой текст — запрашивается из ows по номеру договора (`id` позиции).
3. Номера в ows запрашиваются пачками по 50; позиция берётся по `unitIndex` с валидацией совпадения кода `refEnstruCode` (при несовпадении — поиск по коду в пределах договора).
4. Удаление выполняется **только по тексту** (если текста нет ни в одном источнике или нет ключевого слова «интерактив»/«interactive»).
5. Договоры, не ответившие ни в одном источнике, фиксируются в `contractsNotFoundBoth`.
6. Счётчик позиций без описания в `src/kz/market/filterUnits.ts` опирается на `requiresTextFilter(code, cfg)` из `config.ts`, не дублируя регулярное выражение.

   - Тест на заглушках: договор отсутствует на zakup, в ows содержит `Plans` со словом «интерактивная» -> остаётся; в ows `Plans: null` -> удаляется.
   - Тест на отслеживание договоров, не найденных ни в одном источнике.
