# TDD: «Рынок ИП» — только интерактивные панели

## Контекст и решение

С 01.11.2026 в группу ИП входил весь код ЕНС ТРУ `279020.100.*` («Панель жидкокристаллическая») как отдельный вид «Жидкокристаллические панели». Под этим кодом закупаются обычные мониторы, видеостены, LED-экраны и цифровые табло, что искажало аналитику пульта и завышало рынок более чем в два раза.

**Решение руководителя:** позиция с кодом `279020.100.*` учитывается в рынке, только если в описании есть слово «интерактивная» («интерактивті», «interactive»). Отдельный вид «Жидкокристаллические панели» убирается, прошедшие фильтр позиции считаются как «Интерактивные панели».

## Правило

- Код `279020.100.*` требует текстовый фильтр `textPatterns: ["интерактив", "interactive"]` (регистр не важен).
- Текст позиции составляется из `name_ru`, `extra_description_ru` и `extra_description_kk` (казахское «интерактивті» входит по префиксу «интерактив»).
- Если текста нет или слова нет — позиция исключается из рынка.
- Коды `262030.*` и вся группа КТ текст не требуют и работают как прежде.
- В источнике zakup текст берётся из `plan_item` позиций договоров.
- В источнике ows запрашивается `Plans { nameRu extraDescRu extraDescKz }`; позиции ЖК без описания пропускаются с логом `[Рынок] ows: N позиций ЖК без описания пропущено`.

## RED

- `tests/kz/marketFilter.test.ts`:
  - `classifyCode("279020.100.000001", cfg, text)` с «интерактивная» возвращал `{ group: 'ИП', kind: 'Жидкокристаллические панели' }` вместо `Интерактивные панели`.
  - `classifyCode` без текста или без ключевого слова возвращал вид вместо `null`.
  - `filterContractUnits`: 3 позиции ЖК (интерактивная, лед-экран, без описания) попадали все (length 3 вместо 1).
- `tests/kz/marketZakupFetch.test.ts`:
  - `fetchZakupMarketUnits` возвращал 2 позиции вместо 1, не отфильтровывая неинтерактивную ЖК-позицию.
- `tests/kz/marketOwsFetch.test.ts`:
  - `fetchMarketContracts` не пропускал ЖК-позиции без `Plans` и не выводил лог `[Рынок] ows: 1 позиций ЖК без описания пропущено`.

## GREEN

1. `config/market-monitor.json`:
   - Убран отдельный вид `Жидкокристаллические панели`.
   - В вид `Интерактивные панели` добавлен паттерн `^279020\.100\.` с `textPatterns: ["интерактив", "interactive"]`.
2. `src/kz/market/types.ts`:
   - В `MarketKindConfig` добавлено поле `textPatterns?: string[]`.
3. `src/kz/market/config.ts`:
   - `classifyCode(code, cfg, text)` проверяет `textPatterns` без учёта регистра; при отсутствии текста или слова возвращает `null`.
   - Добавлена функция `matchesMarketCode(code, cfg)` для проверки потенциального попадания кода в рынок (независимо от текста).
4. `src/kz/market/filterUnits.ts`:
   - `extractUnitText(u)` объединяет `text`, `plan_item` (`name_ru`, `extra_description_ru`, `extra_description_kk`) и `Plans` (`nameRu`, `extraDescRu`, `extraDescKz`).
   - `filterContractUnits` передаёт текст в `classifyCode` и считает пропущенные ЖК без текста через `options.onSkippedLcdWithoutText`.
5. `src/kz/market/fetchZakupMarket.ts`:
   - `ZakupSubject` типизирован с полями `plan_item.name_ru`, `extra_description_ru`, `extra_description_kk`.
   - Кандидаты договоров фильтруются по `matchesMarketCode(code, cfg)` (не отсекая ЖК-договоры до чтения позиций).
   - `toRawContract` передаёт объединённый текст позиции в `RawContractUnit`.
6. `src/kz/market/fetchMarket.ts`:
   - В `CONTRACT_QUERY` добавлен запрос `Plans { nameRu extraDescRu extraDescKz }`.
   - При наличии пропущенных ЖК-позиций без текста пишется лог: `[Рынок] ows: N позиций ЖК без описания пропущено`.
7. `src/bitrix/salesPult/page/pult.client.js`:
   - Подпись источника на вкладках рынка обновлена: `госзакупки · zakup.gov.kz`.
8. `scripts/market-filter-lcd.mts`:
   - Скрипт пересборки кэша 2026: обходит месяцы, запрашивает договоры и позиции на zakup.gov.kz, фильтрует через `classifyCode`.
