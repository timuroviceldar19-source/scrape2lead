## GREEN и решения

- `GZ_PORTAL_HANDOFF=1` разрешает передачу только при первой проверке с кодом 75,
  если робот не начинался. Код 76, состояние handoff, явная строка в логе, без sleep.
  Без включателя прежний путь; inconclusive запускает робота. После старта робота
  остаются прежние повторы на той же машине, даже если следующий probe вернул 75.
- `gz-automation.yml` удерживает прежнюю concurrency-группу на всю цепочку.
  Три последовательных вызова `gz-automation-machine.yml` создают отдельные jobs.
  Следующий разрешён только после успешного job с handoff=true.
- Общие шаги одной машины вынесены без копирования. Секреты явно переданы
  через оба уровня workflow_call. Новых permissions нет.
- Включатель передачи равен 1 только на машинах 1/2. Шаг перехватывает только 76,
  экспортирует handoff и завершает job зелёным. Только код 0 экспортирует collected.
  Выходы шага передаются через job и workflow_call outputs.
- `collection-result` с always() требует collected=true хотя бы у одной машины.
  Пропуск следующей машины после передачи не может дать ложный зелёный запуск.
  `deal-outcomes` по-прежнему один раз после pk-plans (всей цепочки), при любом итоге.
- Имя артефакта машины 1 прежнее; машины 2/3 имеют суффиксы -machine-2/-machine-3.
  Лог и marker включены явно. При handoff кэш плана не сохраняется: неизменяемый
  ключ остаётся свободным для машины, выполнившей сбор.
- Summary узнаёт handoff и не читает старый manifest. Состояние связано с run id,
  run attempt и номером машины (GZ_PORTAL_MACHINE в env job), чужое игнорируется.
- Ручной choice simulate_portal_block (0–3, default 0) передаётся через оба уровня.
  На первых N машинах probe не вызывает npx/сеть и пишет явное
  `portal probe: unreachable: simulated`; остальная логика настоящая.
- Guard, watchdog, Worker, probe-модуль, NETWORK_PATTERN, Bitrix и таймауты не менялись.
