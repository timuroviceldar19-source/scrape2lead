# Пульт F3 · «Утренний пульс» и дайджест директору (dry-run)

21.11.2026 · ветка `feat/pult-dec-pulse` от `5127be9`.

Цель: директор в 9:00 с телефона (375 px) за 30 секунд видит, где горят деньги, маржа или крупный
тендер, и одним тапом уходит к списку. Сигналы, которые нельзя пропустить, собираются текстом для
чата — только сборка, без отправки.

## Что сделано

- `src/bitrix/salesPult/pulse.ts` — чистый модуль: `buildMorningPulse`, `pulseForPayload` (главная
  полного пульта), `buildManagerPulse` (вид менеджера), `selectHotLots` (горящие лоты менеджера),
  `formatLotDeadline`, `rankPulseItems`, пороги `PULSE_*`, ссылки `PULSE_LINKS`.
- `payload.pulse` (`types.ts`) собирается в `scripts/sales-pult.mts`, режим site, после
  `attachRegisterContracts` (нужны сигналы договоров). Сбой сборки пульта не роняет пульт: страница
  без пульса, в лог — только класс ошибки.
- Секция `#pulse` над «01» (`pult.html`), рендер `renderPulse` в `pult.client.js`, стили в `pult.css`
  рядом со «Срочно».
- `chatReport.ts`: `buildDirectorDigest(pulse, pultUrl)` и необязательный `hotLots` в
  `buildMorningReport`.
- Утренний режим: радар (`collectRadarView` без `planDeals`) и финансы (`loadFinanceView`), каждая
  загрузка в `catch`; в лог только `[DRY-RUN] Дайджест директору сформирован (пунктов N, длина M симв.)`.
  `--print-digest` печатает текст только при `CI !== "true"`. Пути отправки дайджеста нет.

## Правила пульса

| Пункт | Цвет | Ссылка |
|---|---|---|
| Кассовый разрыв: `cashGap < 0` (деньги минус календарь и КПН, как на «Финансах») | красный | `./fin.html#f-payments` |
| Долги старше 60 дней (в деталях — всего старше 30) | красный | `./fin.html#f-debtors` |
| Долги старше 30 дней, если старше 60 нет | жёлтый | `./fin.html#f-debtors` |
| Подать сегодня, по группе ИП/КТ: число и сумма | красный, если есть лот < 4 ч, иначе жёлтый | `#radar-ip` / `#radar-kt` |
| Крупные лоты: конец приёма в ближайшие 48 ч, не сегодня, от 50 млн ₸ | жёлтый | `#radar-ip` / `#radar-kt` |
| Продажи ниже себестоимости (убыток) | красный | `./reg.html#r-risks` |
| Маржа ниже 10% (выручка) | жёлтый | `./reg.html#r-risks` |
| Склад без движения от 1 млн ₸ | жёлтый | `./fin.html#f-stock` |
| Ошибки в CRM: сигналы договоров + «выиграно на портале, закрыто проигрышем» | жёлтый | `#signals` |

Не больше 6 пунктов: сначала цвет, потом деньги (`amount`), при равенстве — порядок источников.
Повторные ключи отбрасываются, сколько не вошло — в `more`.

## Решения

- **Долги без двойного счёта.** «Старше 60» входят в «старше 30», поэтому пункт один: красный по 60+
  (сумма 30+ — в деталях, если она больше), иначе жёлтый по 30+. Суммы — ровно из
  `buildFinanceInsights(finance, asOfDate)`, на ту же дату, что страница «Финансы».
- **Порог склада** `PULSE_STOCK_MIN_SUM = 1 млн ₸`: неподвижные остатки есть почти всегда, мелочь —
  шум. Ссылка на секцию `#f-stock`, а не `#stockFocus`: `fin.client.js` сейчас правит агент «Склад»,
  id секции стабильнее.
- **Тендеры по группам.** Пункт на ИП и отдельно на КТ, чтобы ссылка вела в нужную вкладку радара.
  Берётся только колонка «Подать» (`submitToday`), как в KPI самого радара.
- **Часы от `nowIso`.** Часы до конца приёма и «сегодня» пересчитываются от момента сборки по `endAt`
  (истёкшие лоты выпадают). Разбор времени Алматы продублирован в `pulse.ts`: `radar/aggregate.ts` —
  зона агента «Радар», экспорт оттуда не добавлялся. В деталях — абсолютное время («до 11:00»), а не
  «через 2 ч»: страница статична и открывается позже сборки.
- **Реестр только текущего месяца.** Файл за прошлый месяц (первые дни месяца) — пунктов маржи нет,
  в `missing` «Реестр: файла за ноябрь ещё нет»: прошлый месяц уже разобран на «Выручке». Срез старше
  3 дней — пометка «Реестр: данные на …».
- **`missing`.** Финансы не переданы или с ошибкой — «Финансы: нет отчёта»; отчёт старше 3 дней —
  «Финансы: отчёт на 16.11» и та же пометка в деталях финансовых пунктов. Радар `null` — «не
  загружен», с `error` — «не загрузился», не передан — не проверялся (так же реестр).
- **Расширения контракта.** `PulseItem.amount?` (деньги для сортировки; у `extraItems` без суммы —
  конец своего цвета) и `PulseView.more?`. Остальные поля — как в задаче.
- **Вид менеджера.** `filterPultPayload` копирует payload через `...rest`, поэтому полный пульс ушёл бы
  менеджеру — тест это поймал (RED ниже). В `buildManagerVariant` пульс заменяется на
  `buildManagerPulse(pult.radar, …)`: только тендеры радара варианта. Сейчас там `radar: null`, пульс
  пустой с пометкой «Радар: не загружен»; после слияния с «Радаром» придёт его личный радар.
  Страница дополнительно отбрасывает пункты `finance: true` при `viewer`. Закрытым месяцам пульс не
  собирается (`pulseForPayload` → `null`).
- **ТВ.** `body.tv #pulse { display: none }` (плюс общее правило `body.tv section.block`), в `SCENES`
  пульса нет — список сцен не менялся.
- **Страница.** Ссылки — только `#…`, `./…`, `https://…`. У ссылки `aria-label` со словом цвета
  («Срочно», «Внимание»), точка и стрелка `aria-hidden`. На ≤600 px строка — две строки: заголовок и
  «значение · детали» с многоточием; на 1440 — одна строка. Анимации появления нет: пульс виден сразу.
- **Дайджест.** Обычный текст: маркер `#дайджест <дата> директор`, строки 🔴/🟡/🟢, «Нет данных: …»,
  одна ссылка на пульт в конце (по ссылке на каждый пункт текст на телефоне вдвое длиннее). Теги
  вырезаются.
- **Утренний режим без реестра.** Реестр тяжёлый (Диск, история, сверка), поэтому в утреннем дайджесте
  пунктов маржи нет — они есть на сайте. `loadFinanceView` в утреннем режиме ведёт себя как в site:
  при `REGISTER_HISTORY_KEY` обновляет зашифрованный кэш `data/register/finance.json`.
- **Горящие лоты.** Окно 24 ч может перейти через полночь: строка «🔥 Срок подачи сегодня: …» или
  «🔥 Срок подачи завтра: …» по дате конца приёма (Алматы). Без `hotLots` отчёт байт в байт прежний.

## Что подключить при слиянии

- Агент «Радар»: личный радар менеджера в `filterPultPayload` — пульс менеджера подхватит его сам
  (`pult.radar`), правок в `pulse.ts` не нужно.
- Агенты «Потери» и «Склад»: свои пункты — через `extraItems` в `pulseForPayload(payload, { …, extraItems })`
  в `sales-pult.mts` (`area: "losses"` / `"stock"`, `finance: true` для денег группы, `amount` для порядка).
  Если «Склад» даст свой пункт склада, финансовый `stock-stagnant` стоит убрать: при одинаковом `key`
  остаётся первый, а финансовые пункты идут раньше `extraItems`.

- RED: `tests/bitrix/salesPultPulseSources.test.ts` — 3 failed (нет `lossPulseItems`).

  `skipUpdates` (тесты) база не читается вовсе — иначе локальный прогон читал бы настоящую базу. Сбой загрузки
  пишет класс ошибки и дайджест не отменяет. Номера лотов в лог не попадают (тест в `salesPultMorningPulseLogs`).
