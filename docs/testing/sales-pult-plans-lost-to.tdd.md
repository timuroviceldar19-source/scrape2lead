# Пульт, «Планы»: кому проиграли (Д6)

## Задача

На «Планах» видно, сколько закупок «ушло конкурентам», но не видно, кому именно и почему.
Робот исходов (`check-gz-deal-outcomes`, `buildGzDealOutcomeComment`) пишет победителя только
в комментарий ленты сделки: «Итог закупки: выиграл <поставщик> (БИН …) — договор №… от …, <сумма> ₸».
В полях сделки остаётся только ключ `lost:<номер договора>` (`UF_CRM_S2L_GZ_OUTCOME`).

## Решения

- `src/bitrix/salesPult/plans/lostTo.ts`:
  - `parseLostOutcomeComment` разбирает комментарий: название (в нём могут быть скобки и `&quot;`),
    БИН из 12 цифр и сумму договора (разделители — обычный и неразрывные пробелы, дробная часть через запятую).
    Победа партнёра («выиграл наш партнёр …»), наша победа, расторжение и прочие комментарии не считаются.
  - `attachLostWinners` читает комментарии только проигранных сделок по планам (`outcomeCategory === "lost"`),
    по 50 сделок в одном `batch` (`crm.timeline.comment.list` есть в белом списке `ReadOnlyBitrixClient`).
    Если у сделки несколько комментариев об исходе, берётся последний по ID.
    При сбое пачки сделки остаются без победителя. Текст ошибки не выводится, потому что в нём может быть адрес вебхука.
- `buildSingleSliceView` добавляет `lostTo` в каждый срез, то есть в «все месяцы» и в каждый месяц:
  - число проигранных закупок, число компаний-победителей, число сделок без данных о победителе;
  - топ-15 компаний по числу закупок, при равенстве — по сумме плана;
  - для каждой компании: сумма плана, сумма известных договоров, «дешевле плана в N из M»
    (договор меньше плана больше чем на 0,5%) и 20 крупнейших сделок — так же, как в других списках «Планов».
- Медианную скидку не показываем. На настоящих данных (10.11, 466 сделок с суммой плана) у половины
  договор совпадает с планом, а у 61 сделки он ниже плана больше чем на 50%: договор, видимо,
  закрыл только часть количества. Медиана по компании из-за этого вводила бы в заблуждение.
  Процент по каждой сделке виден в раскрывающемся списке, а в примечании блока сказано, когда он занижен.
- Блок «04 Кому проиграли» стоит после «Способов закупки» и перед «Открытыми планами».
  Открытые планы стали 05, крупнейшие заказчики — 06. Контейнер называется `.lost-to`,
  потому что класс `.lost` уже занят блоком «Крупные договоры не у нас» на «Рынке».

## Проверка на настоящих данных

Локальная сборка `--mode site` 10.11 (только чтение, данные не в репозитории):

- победитель найден у 405 из 405 проигранных сделок по планам (ИП 163, КТ 242);
- компаний-победителей: ИП 67, КТ 113;
- у лидеров КТ 38 и 22 закупок, у лидеров ИП — 20 и 19;
- шаг «Планы» вместе с комментариями занимает около 18 секунд.

Партнёр «Торговая сеть Казахстана» не внесён в `partnerBins` (`config/gz-deal-outcomes.json`),
поэтому робот записывает его победы как проигрыш, и он появится в этом списке среди конкурентов.
Вносить ли его в партнёры, решает владелец конфигурации; этот PR конфиг не меняет.
