# Группы планов по товару

## Задача и границы

Группа плана определяется товаром, а не закупочной воронкой. Меняем только монитор
планов: сделки, воронки, конфигурацию Рынка и workflow не меняем. Обогащение имён
менеджеров и интерфейс фильтров остаются отдельными этапами.

## RED

Сначала обновлён `tests/bitrix/salesPultPlansMonitor.test.ts` и выполнен профильный
прогон. Получены пять ожидаемых падений: зависимость группы от воронки,
неверный вид компьютера и отсутствие исключения посторонних товаров.
Остальные тесты файла прошли.

## Решения

- Для непустого кода используем `groups[group].prefixes` из
  `config/market-monitor.json` через существующий `loadMarketConfig`.
  Список префиксов в мониторе не дублируем, маршрутизацию сделок не используем.
- Название товара (включая прежний резерв из заголовка) используется только
  при отсутствии кода. Неизвестный непустой код не переопределяем названием.
- При отсутствии подходящей группы возвращаем `null`. Услуги, ремонт,
  обслуживание и аренду без кода исключаем до проверки товарных слов.
- Проверка принадлежности сделки к планам вынесена в общий предикат.
  `[Планы] вне групп: N` считает только подходящие планы, а не лоты и чужие сделки.
- Суффиксы видов 11, 13, 21 и 43 ограничены полным префиксом `262030.100.`.
- Больше не запрашиваем поля ключевых слов, нужные прежней маршрутизации.
