# F3 B2B: поля сделки по лоту — TDD evidence

## User journey

Менеджер открывает сделку воронки `F3-B2B тендеры`, заведённую по лоту Самрук-Казыны (например, `[SAMRUK 4586672] АО "ИЦА"`),
и видит пустые «Ссылка на Заказчика», «Адрес», «Количество / объем», «Цена за единицу». У сделок по планам эти поля
заполнены, потому что их даёт карточка пункта плана (`planDetail`), а у лотов её нет.

## Что отдаёт EPZ по лоту (проверено 25.11.2026)

- `/lots/`: `quantity` есть у всех лотов (выборка 100 SKK + 100 Mitwork), `total_price` — сумма лота. Единицы измерения
  нет, `delivery_addresses` пустой у всех 200 лотов, `customers` пуст у 16% лотов SKK.
- `/announcements/{id}/`: `customer.id` — карточка заказчика в реестре (`/registry/pipp/{id}`), `customer.address` —
  юридический адрес (`kato.full_name_ru`, `street`, `house`). Обогащение уже ходит сюда за БИН лота.

## Key decisions

- Количество и цена за единицу лота кладутся в `lotQuantity` / `lotUnitPrice` записи, а не в `planDetail`: пустой
  `planDetail` у лота менял бы классификацию и сверку года плана. Цена за единицу — `total_price / quantity`, до копеек.
- Заказчик лота по-прежнему берётся из объявления (как и раньше, ради БИН), оттуда же теперь `customerSourceId` для ссылки
  и `customerAddress`.
- «Адрес» (`UF_CRM_DELIVERY_ADDRESSES`) у лота заполняется юридическим адресом заказчика; места поставки плана имеют
  приоритет. Тот же адрес пишется в `UF_CRM_6A436D59AACBF`, если нет профиля goszakup.
- Единицу измерения не выдумываем: EPZ её для лота не публикует, поле остаётся пустым.
- Уже созданные сделки по лотам дозаполнит следующий прогон: обновление пишет все поля, `undefined` не затирает ручные.

## Срок приёма заявок в карточке (25.11.2026)

Сборщик писал срок приёма заявок только в `BEGINDATE`/`CLOSEDATE`, а карточка воронки «F3-B2B тендеры» этих полей не
показывает. В разделе «Закупка» есть свои поля: «Тендер» (`UF_CRM_1713514302985`, ссылка), «Начало приема заявок»
(`UF_CRM_1713515014882`) и «Окончание приема заявок» (`UF_CRM_1713515048879`). У сделки ИЦА 58393 они были пустыми, и
менеджер не видел срок.

- У опубликованного тендера (`recordKind: "tender"`) эти три поля заполняются из тех же дат и ссылки на лот.
- У плана поля не трогаются: срока приёма у плана нет.
