# TDD: реестр ОП из папки задачи «Ежедневный отчет по Продажам»

## Где лежит реестр
- Файлы «ОП дд.мм.гг.xlsx» каждый день прикрепляют в задачу 36277 «Ежедневный отчет по Продажам».
- Чат задачи — `chat53225`. Папка файлов чата на Диске — `89975` (`im.disk.folder.get`, `CHAT_ID=53225`).
- Это значение стоит в `config/sales-pult.json` → `register.diskFolderId`.
- Вебхуку нужно право `disk`. Ссылка `urlDownload` из сообщения чата отдаёт вебхуку страницу входа, а не файл. Скачивание работает только по `DOWNLOAD_URL` из `disk.folder.getchildren`.

## RED
- `fetchLatestRegisterFromDisk` получал пустой список.
  - Он ждал от `client.call` ответ вида `{ result: [...] }`, а `BitrixClient.call` возвращает уже сам `result`. Поэтому реестр не нашёлся бы даже с правом `disk`.
  - Кроме того, читалась только первая страница (50 элементов), а в папке уже 61 файл.
- Тест `fetchLatestRegisterFromDisk` в `tests/bitrix/salesPultRegisterParse.test.ts`: 60 файлов на двух страницах, последний реестр — на второй. Падал с `unexpected disk.folder.getchildren`.

## GREEN
- Список папки берётся через `listAllBatched("disk.folder.getchildren", { id })`: все страницы, батчем.
- Живой прогон `--mode site` (29.10): взят «ОП 28.10.26.xlsx», `[Реестр] строк: 96, договоров: 84, найдено в CRM: 66, нет в CRM: 18`.
- Данные реестра есть только в `reg.html`, в `index.html` и `payload.json` их нет.

## До слияния
- Для `/reg` нужно отдельное приложение Cloudflare Access, только для руководства. Иначе реестр (закупочные цены, маржа, бонусы) откроется тем же входом, что пульт и ТВ.

## Сверка файла прошлого месяца (01.11)

- Пока в папке нет файла ОП за новый месяц, последний файл — за прошлый. Сверка с CRM брала
  переходы на «Договор» из прогона пульта, то есть с начала текущей недели или месяца,
  поэтому в первые дни месяца почти все договоры файла показывались на `/reg` как «нет в CRM».
- RED: `tests/bitrix/salesPultRegisterFileMonth.test.ts` — файл «ОП 30.10.26.xlsx» при дате
  2026-11-02 и пустых переходах пульта: оба договора попадали в `missing`.
- GREEN: если месяц файла раньше текущего, `loadRegisterView` берёт выигрыши CRM за месяц файла
  через `fetchCrmWonDealsForMonths` (как история). Договоры без пары ищутся и среди сделок,
  закрытых в следующем месяце: договор подписан в конце месяца, сделку закрыли позже. Лишними
  считаются только сделки месяца файла. Для файла текущего месяца всё по-старому, без лишних
  запросов (второй тест это проверяет).
- Если выигрыши за месяц файла не загрузились, сверка идёт по переходам пульта, причина пишется
  в лог; страница реестра не падает (это проверяет старый тест на сбой `crm.stagehistory.list`).
