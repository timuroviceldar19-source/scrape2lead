# TDD: «Потери по причинам» во вкладке «Конкуренты» (`pult-losses-by-reason`)

РОП и тендерный специалист видят, сколько денег группа F3 (F3 + партнёры) теряет и почему: заявки отклонены
(документы на ПО, письмо производителя, несоответствие ТС, обеспечение, прочие документы), проиграли по цене,
проиграли по условной скидке. Отдельно — свежие отклонения при цене ниже победителя. Действие из блока:
«исправить пакет документов по главной причине».

Все данные в тестах выдуманные (`tests/fixtures/kz/competitorsLosses.ts`: БИН `9000000000xx`, лоты `LS-*`/`LK-*`).

## Контракты

- `src/kz/competitors/losses.ts`
  - `classifyRejectionReason(short: string, detail: string): LossReasonKey`
  - `LOSS_REASON_LABELS: Record<LossReasonKey, string>` — русские подписи, только здесь
  - `buildLossBreakdown(slice: Pick<CompetitorsGroupSliceView, "ourRejections" | "headToHead">, cfg?: { allOurBins?, asOfDate?, recentDays?, maxLotsPerReason? }): LossBreakdown`
  - `summarizeRecentCheaperRejections(view: CompetitorsView, asOfDate: string, days = 7): { count; sumOur; items[] }`,
    элемент: `group`, `lotNumber`, `date`, `kind`, `ourPrice`, `winnerPrice`, `url` (+ `ourCompany`, `customerName`)
- `src/kz/competitors/types.ts`: `LossReasonKey`, `LossLotLink`, `LossReasonRow`, `LossHeadToHeadBucket`, `LossBreakdown`;
  новое поле `CompetitorsGroupSliceView.losses` (и в общем срезе, и в `monthViews`); `OurRejectionItem.endDate?`.

## Решения

1. **Деньги** — `ourPrice` (`bidTotalPriceNoVat`, сумма нашей заявки без НДС), как в источнике. Суммы округляются до тенге.
2. **Лот считается один раз** (`annoId` + `lotNumber`), даже если отклонили и F3, и партнёра. Из нескольких отклонённых заявок
   группы в лоте берётся «представитель»: сначала дешевле победителя, затем с наименьшей ценой. Его причина и сумма идут
   в разбивку, поэтому сумма по причинам всегда равна итогу (проверяется тестом).
3. **Лот, который всё равно выиграла компания группы** (F3 отклонили, партнёр победил), потерей не считается. БИН группы —
   `cfg.allOurBins`; в `summarizeRecentCheaperRejections` конфига нет, поэтому БИН группы берутся из самого вида:
   строки `competitors` с `us: true` и `ourBin` отклонений.
4. **Проигрыши в очных встречах** — из полного списка `headToHead` до обрезки до 50 лотов на соперника (в `aggregate.ts`
   `buildLossBreakdown` получает `h2hMap.values()`). Берутся лоты с `rivalWon && !weWon` и причиной `price` или
   `cond_discount`; лот, повторяющийся у разных соперников, считается один раз. `sumGap` = наша цена − цена победителя
   (у проигрышей по условной скидке обычно ≤ 0: мы были дешевле, но проиграли по условной цене). Дополнительно к заданию
   добавлен `sumOur` — сумма наших заявок в проигранных лотах: это и есть «потеря в деньгах», а `sumGap` показывает,
   на сколько надо было быть дешевле. `our_rejected` здесь не считается — он уже в отклонениях.
5. **Свежесть** считается по дате окончания приёма заявок (`OurRejectionItem.endDate`, из `CompetitorLot.endDate`), а если её
   нет — по дате начала лота. Даты протокола итогов в данных лота нет; дата начала лота для окна в 7 дней не годится
   (открытый конкурс идёт дольше, окно было бы почти всегда пустым). Окно — `(asOf − days; asOf]`: при `asOf = 21.11`
   и 7 днях входят 15.11…21.11, 14.11 и будущие даты не входят. Ограничение: если протокол вышел позже чем через неделю
   после окончания приёма, такое отклонение в «свежие» не попадёт (видно в общей разбивке).
6. **Размер.** В разбивке нет текстов причин и названий заказчиков; на причину — до 10 ссылок (сначала дешевле победителя,
   затем по сумме), в `recentCheaper` — до 10. В причины попадают только встретившиеся категории. Синтетика на 300 выдуманных
   отклонённых заявок по 11 месяцам: +85 КБ на `losses` во всех срезах ИП и КТ и +20 КБ на `endDate` (меньше 1% страницы).
7. **Классификатор** — регулярки по нормализованному тексту `short + detail` (нижний регистр, ё → е, без кавычек).
   Порядок: обеспечение заявки → документы на ПО → письмо производителя → несоответствие ТС → прочие документы → другое.
   - «Программное обеспечение» заменяется токеном до проверки обеспечения, иначе «ПО не внесено в реестр» стало бы
     «обеспечением заявки». То же для казахского «бағдарламалық қамтамасыз ету» (в нём есть «қамтамасыз ету»).
   - «ПО» узнаётся только заглавными как отдельное слово и только если в тексте есть строчные буквы (иначе это предлог).
   - Документы на ПО: «лицензи…», «реестр доверенного…» всегда; упоминание ПО — только вместе с документом
     (документ, письмо, правообладатель, сертификат, реестр, подтверждение). «Не соответствует ТС, нет встроенного ПО»
     остаётся несоответствием ТС.
   - «Письмо правообладателя ПО» — документы на ПО; «письмо правообладателя» без ПО — письмо производителя.
   - «Сертификат» без ПО (например, о происхождении товара) — прочие документы, а не ПО.
   - «Несоответствие КД», «не соответствует требованиям конкурсной документации», «иные основания» — `other`: конкретной
     причины в тексте нет. Поэтому «документ» в регулярке — без «документации».
   - Казахский: только надёжные ключи — «өтінімді қамтамасыз ету» (обеспечение заявки), «бағдарламалық қамтамасыз ету» +
     «лицензия» (ПО), «техникалық ерекшелік/сипаттама» (ТС), «өндірушінің хаты» (письмо производителя), «құжат»,
     «ұсынылмаған», «қол қойылмаған», «ЭЦҚ» (документы). Остальное — `other`.
8. **Интерфейс** (`page/competitors.client.js`, только рендер): новый первый блок «Потери по причинам», нумерация блоков
   теперь считается счётчиком (если в старой выгрузке нет `losses`, блок пропускается и нумерация начинается с 01).
   Итог одной строкой, свежие отклонения, «главная причина» (первая по сумме, кроме «Другое»), полосы по причинам
   (`<details>` со ссылками на лоты), строка проигрышей. Блок учитывает выбранный месяц (`monthViews`). «Наши отклонения»
   свёрнуты под `<details>` по умолчанию (анти-шум). `aria-labelledby` у секции, полосы `aria-hidden` (цифры есть текстом).
   Тест `salesPultCompetitors.test.ts` теперь раскрывает список отклонений перед чтением текста.
9. **Роли**: у менеджера `competitors: null` (как и раньше), данных потерь в его странице нет; на ТВ вкладки нет.
10. **Утренний пульс** не тронут: `summarizeRecentCheaperRejections` подключит интегратор.
