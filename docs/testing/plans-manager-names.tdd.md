# Имена менеджеров в мониторе планов

## Границы

Этап 2. Ветка создана от свежего `origin/main` после слияния этапа 1.
Меняем только обогащение имён в планах и связанные тесты. Доступа к рабочему
Bitrix нет; реальные имена и суммы не используются в тестах и документации.

## RED

Сначала обновлены тесты `tests/bitrix/salesPultPlansMonitor.test.ts` под
`im.user.get`: отдельный числовой ID, уникальность запросов, неактивный
сотрудник, полное имя и резервные части имени, сохранение профиля/конфига/ID,
изоляция сбоя одного запроса и безопасный лог ошибки с вымышленным URL.
Профильный прогон до изменения реализации: пять ожидаемых падений.

## Решения

- Вместо недоступного `user.get` используем `im.user.get` через
  `ReadOnlyBitrixClient`, как основной сборщик пульта.
- По одному последовательному запросу на уникальный непустой ID, для которого
  нет готового `userProfiles`. Повторные планы одного менеджера не создают
  дополнительных запросов; пустой ID пропускается.
- Имя берём из `name`, при отсутствии — из `first_name` и `last_name`.
  `active=false` не исключает имя сотрудника из исторических планов.
- Каждый запрос имеет отдельный `try/catch`. Сбой не прерывает загрузку
  других имён и не ломает весь монитор.
- При ошибке выводим предупреждение с ID и названием метода. Исходную ошибку
  и её сообщение не выводим: они могут содержать URL вебхука.
- При недоступном/пустом имени сохраняются прежние резервные значения:
  имя из конфига или переданного профиля, затем `ID N`.
