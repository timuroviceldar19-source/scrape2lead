# Сроки приёма заявок в сделках по лотам: журнал TDD

## Проблема

Сделки по лотам (`ORIGIN_ID gz-lot:<номер>`) создаёт `scripts/bitrix-push-gz-lots.mts`. Выгрузка лотов с портала
не содержит дат, и скрипт не передавал `BEGINDATE`/`CLOSEDATE`. Bitrix заполняет их сам: `BEGINDATE` — день создания,
`CLOSEDATE` — +7 дней. Менеджеры читают это поле как срок закупки, а оно им не является.

Замер на живых данных (13.10.2026, только чтение): открытых сделок по лотам 1164, у всех 1164 даты «по умолчанию».
С реестром по `CLOSEDATE` совпали 5, не совпали 1158. Из 44 закупок, где приём заявок идёт сейчас, у 12 в Bitrix срок
уже «прошёл», у остальных стоит не тот день (например, сделка 48667: в Bitrix 20 октября, в реестре приём до 15 октября 15:35).

## Решение

- Срок берём из реестра по **номеру лота** (`Lots(filter:{lotNumber}) { TrdBuy { startDate endDate } }`), как в боте
  (`lot_info`). Число до дефиса в номере лота — старый пункт плана, ключом оно не служит.
- Поле сделки Bitrix хранит только дату, поэтому в `BEGINDATE`/`CLOSEDATE` идёт день, а часы (время Алматы)
  добавляются строкой «Приём заявок: …» в комментарий новой сделки.
- Реестр не ответил или лота в нём нет — сделка создаётся, как раньше, в логе `[dates-missing]`; ничего не падает.
- Уже созданные сделки правит отдельный скрипт `scripts/bitrix-backfill-gz-lot-dates.mts`:
  по умолчанию просмотр, запись только с `--execute` (пробно — `--limit 5`).
  Меняет только `BEGINDATE`/`CLOSEDATE` и только у открытых сделок, где даты стоят «по умолчанию»
  (`BEGINDATE` = день создания, `CLOSEDATE` = +7 дней). Даты, которые менеджер поправил руками, не трогаются.
  Запись идёт без `REGISTER_SONET_EVENT`, чтобы массовая правка не засыпала живую ленту.

## Срез 2: проводка в скрипты

- `bitrix-push-gz-lots.mts`: перед `crm.deal.add` читает срок из реестра (если задан `GOSZAKUP_TOKEN`, он есть в
  workflow), кладёт даты в поля сделки и строку в комментарий; в dry-run выводит найденный срок.
- Проверено вживую на пробной выгрузке из двух строк (настоящий лот и выдуманный): срок найден и показан /
  «срок приёма заявок не найден», dry-run, в Bitrix ничего не записано.
- `bitrix-backfill-gz-lot-dates.mts`, просмотр на живых данных: открытых сделок по лотам 1164, к исправлению 1162,
  уже верно 1, в реестре нет дат 1, сбоев чтения нет, сделок с датами, правленными вручную, нет.
  Скрипты не входят в `tsc` (`include` — `src` и `tests`), поэтому проверка прогоном обязательна.
